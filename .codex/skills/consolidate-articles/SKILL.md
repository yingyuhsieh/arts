# Consolidate Articles

整合藝術家或單一藝術作品的多份文章，產出內容可靠、資訊充足、適合 NotebookLM 製作介紹影片，也適合直接放到 Blog 閱讀的敘事文章。

## 輸入與輸出

- 讀取使用者指定的所有素材，包括 Claude、ChatGPT 與其他來源的文件。使用者只提供資料夾時，先辨識與主題相關的文章，不把無關藝術家或作品混入。
- 以 Claude 文章為主草，保留有用的敘事主線，但不把 Claude 或其他 AI 文件當作事實證據。沒有 Claude 草稿時，以最完整且最切題的文章為基礎，並在交付時說明。
- 保持使用者指定的語言；未指定時沿用主草語言。中文使用繁體中文與臺灣慣用語。不自動增加雙語版本。
- 將 UTF-8 Markdown 存在相關藝術家或故事資料夾，檔名為 `<artist_name> (complete).md` 或 `<artwork_name> (complete).md`，保留名稱中的歷史重音符號。不要改動原始素材。若同名成品已存在，先讀取並依本次要求更新，不盲目覆蓋既有獨有內容。

## 整合與查核

1. 完整閱讀各份文章，辨識重複內容、各稿獨有且有價值的資訊、互相矛盾的說法，以及需要查證的關鍵主張。這份工作比較可留在內部，不必變成額外交付文件。
2. 對重複內容重新寫成清楚、有連貫性的段落，保留最好的細節與解釋，避免逐段拼貼、重複介紹或保留多個版本。
3. 對可增加理解的獨有內容，查核後融入主線。優先補足與主題相關的背景、作品與技法、委託或創作情境、意涵、接受史、影響，以及收藏或流傳歷史；依題目取捨，不必把每項寫成固定章節，也不為求完整堆砌無關資料。
4. 使用網路研究驗證重要事實：人物與作品名稱、日期、媒材、尺寸、歸屬、收藏位置、歷史事件、引言與重要解讀。優先使用博物館館藏頁、藝術家或檔案機構、學術出版與原始文獻。來源連結必須實際開啟並確認支持相應主張；AI 草稿與搜尋摘要不能作為最終證據。
5. 解決來源衝突時，依證據品質與適用範圍判斷，不以草稿多數票決定。對爭議歸屬、約略日期或有分歧的解讀保留必要限定語。無法驗證的內容應刪除或明確限定，不補寫成確定事實。若無法取得足夠證據，交付時說明尚未完成的查核，不宣稱全文已驗證。
6. 可保留有助故事的藝術品成交資訊，但不要大量搜尋價格或讓市場資料主導文章。使用時核對作品、拍賣日期、幣別及價格是否包含佣金，並引用拍賣行等可靠紀錄。

## 敘事寫作

用引人入勝且有證據支持的場景、作品細節或核心問題開場，讓讀者理解主角為何值得關注。依故事需要安排段落與簡潔的小標題，使背景、創作選擇及其影響自然銜接；不必沿用主草所有標題或僵硬的年表順序。

正文以 narrative 敘事段落為主，不用條列式羅列生平、作品或分析。把具體視覺細節、歷史情境與解讀連結起來，解釋資訊為何有意義。保持易讀的 Blog 節奏，也提供 NotebookLM 可理解的完整人物與作品指涉。不要虛構對話、心理活動、現場細節或引言，也不要把研究推論寫成已知事實。

在關鍵事實與有爭議的解讀附近加入可點擊的 Markdown 來源連結。文末可用精簡的「參考資料」清單整理實際引用的來源；來源清單可使用條列，正文仍維持敘事。避免把工作比較、查核日誌或給影片生成工具的指令混入公開文章。

## 完成檢查

重新閱讀成品，確認有價值且已查核的各稿內容已融入、重複與矛盾已處理、敘事流暢、來源確實支持主張，並且文章對未讀過原稿的讀者也完整可讀。確認檔名、位置、UTF-8 與 Markdown 格式正確；在 Git 儲存庫中執行 `git diff --check`。

交付時提供成品檔案連結，簡短說明整合結果及任何仍影響可靠性的限制。不要只提供計畫或修改建議，應完成並儲存文章。
